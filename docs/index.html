How it works

Features

Clone & go

The vendored code lives as ordinary files in your repository. You and your collaborators use it like any normal git repo — clone and build, nothing to install.

Two-way sync

pull merges upstream work into your tree; push rebuilds upstream history — every commit of yours arrives individually, original author and message.

Plain git semantics

Branch, merge, rebase, bisect and revert the including repository as usual — the vendored files ride along like any other content.

subrepo-compatible

Same .gitrepo marker format as git-subrepo — adopt an existing git-subrepo project with zero migration.

Pin anything

Track a branch, or pin to a tag or exact commit. switch moves between them in one command, carrying local changes over.

Status & diff

See commits behind, commits to push, and full diffs against upstream — offline, from the last fetch.

Nested includes

Includes can contain includes. Markers travel as content; operate on any level independently.

Export built-in

init turns any directory into a new include, extracting its full history — ready to publish to an empty repo.

One binary

Rust with libgit2 embedded — independent of your installed git version. No temp branches, no hidden state. MSI, conda and a portable Linux build included.
